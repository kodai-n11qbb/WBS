## 1. 全体概要
本システム **「WBSer」** は、中央サーバーを必要としない対等な **分散モード (P2P)**、指定ホストに接続する **クライアントモード (CLIENT)**、および自端末で接続を受け付ける **ホストモード (HOST)** の3つの柔軟な運用形態に対応した、プロジェクト進行管理ツールです。

**「Local-First（ローカルファースト）」** 本ツールでは、全体の構造化と「全体像が見えること」を最優先とし、**Obsidian型ノードグラフ表示を主軸（前面）**に配置した全画面キャンバスと、**GanttProjectスタイルの日付管理ガントチャート**の **2つの主要ビュー構成** とします（従来のツリー・カンバンビューは排し、グラフビューとガントチャートに特化・単純化）。エンジニアリング重視の静かで高コントラストなテキスト主体デザインシステム（Dark / Light モード対応）を提供します。

```
+-----------------------------------------------------------------------------------------+
| [WBSer] [Node: dev-1]   [ ↺ 1つ戻す (Undo) ]   [ グラフ | ガント ]   [ ダーク/ライト ]  |
+-----------------------------------------------------------------------------------------+
|  ┌─────────────────────────────────┐                                                    |
|  │ ← 親要素へ移動: [親タスク名]    │ (左上固定オーバーレイ親ナビゲーションUI)           |
|  └─────────────────────────────────┘                                                    |
|      (親ノード) ← 上方向親リンク視覚表示 (ノードクリックで最上部浮上・配下全展開)         |

|        ◯   ◯ (ノードクリック → 最上部へ焦点移動 ＆ 配下全子要素展開 ＆ サブツリー強調)   |
|             │   ┌────────────────────────────────────────────────────────┐              |
|             └──>│ [タイトル編集] [完了予定日:YYYY-MM-DD] [TODO/進行中/完了] [ルート化] │ |
```

### (1) 端末単位 Undo (1つ戻す) 機能 (Node-Local Undo Mechanism)
- **自端末操作の逆再生・取り消し**: 各イベントに記録された `authorNodeId` を検証し、自端末が最後に行ったアクション（タスク作成・ステータス更新・タイトル編集・親変更・削除等）を即座に打ち消す `UNDO_ACTION` イベントを発行して元の状態に安全復元。

### (2) 進行中 (IN_PROGRESS) ステータス時の完了予定日必須化 (Mandatory Due Date for IN_PROGRESS)
- **日付設定の強制**: ステータスを `IN_PROGRESS`（進行中）に変更する際、完了予定日 (`dueDate`) の入力が必須となります。未入力の場合は UI で完了予定日選択ダイアログが自動ポップアップし、確定するまで更新を適用しません。

### (3) 前面化された Obsidian型 物理グラフィカルキャンバス ＆ 親ナビゲーションUI
- **前面メイン画面化**: アプリの標準画面としてグラフキャンバスを前面に配置。
- **実用重視のテキスト・モノトーンデザイン**: 絵文字やド派手なエフェクトを廃し、Linear / Raycast 風のクリーンなグリッドとソリッド境界線を採用。
- **ノードダブルクリック時の最上部頂点化 ＆ サブツリー限定表示 (Subtree Focus Mode)**:
  - ノードをダブルクリックした際、親要素が存在する場合は対象ノードが一番上の親要素である位置感（画面最上部）に浮上配置され、そこからさらに上方向へと接続リンク線（発光・点線）が伸びるよう視覚描画。
  - 画面上はダブルクリックされた要素とその配下の子孫要素群のみが存在するかのように他要素を非表示化（Subtree Isolation）。
  - サブツリー表示時、画面右端のネスト表示切替（1階層 | 2階層 | すべて）は、現在表示されているサブツリーの親ノードを基準点として相対的に適応・フィルター処理。
- **ノードクリック時の焦点移動 ＆ 親視覚接続表示**:
  - ノードシングルクリック時、対象ノードの親要素が存在することを上方向リンク（発光接続線）で視覚的に明示し最上部焦点移動。
- **インスペクターノード被り・干渉防止 (Inspector Shielding & Layout Protection)**:
  - 要素選択時に表示される詳細インスペクターパネル（ドロワー）が、周囲の子要素ノードやラベル・接続線と重なって隠してしまう問題を防ぐため、物理バネ領域の拡張およびパネル下層の視覚シールド（遮蔽・Z-index保護）を完備。
- **左上絶対配置の親ナビゲーションUI (`.graph-parent-nav`)**:
  - グラフキャンバス左上に `position: absolute; top: 16px; left: 16px;` で固定パネルを配置。
  - サブタスク選択時に `← 親要素へ移動: [親タスク名]` ボタンを表示し、ワンタップで先祖ノードへ瞬時に視点を移動・ナビゲーション可能。
- **Sugiyama風レイヤード・ツリー自動配置 ＆ 交差完全防止 (Sugiyama Untangled Tree Layout)**:
  - 末端タスク数（Leaf Count）の再帰採寸によりサブツリー同士のX座標領域を非交差計算し、線の絡まり・交差を幾何学的に解消。
- **ネスト数による縦方向自動スケール (Dynamic Y Ratio Scaling)**:
  - 可視タスクの最大ネスト数（1〜N階層）に応じてキャンバスの縦領域を自動均等分割。浅い階層でも間延びせず、深い階層でも全てのノードが画面内に美しく収まるダイナミック配置。
- **文字サイズ選択 ＆ キャンバス空白部クリックによるフォーカス解除**:
  - 画面端のコントローラーからネスト表示切替に加え、文字サイズ（小 / 中 / 大）を即座に選択可能。
  - ノード以外のキャンバス空白部分をクリックした際、選択状態（フォーカス）を解除し「何も選択していない初期状態」に即座に復帰。
- **キャンバス内上部ルート化ドロップゾーン (In-Canvas Root Zone)**:
  - キャンバス内でノードをドラッグ中、キャンバス内最上部 (`Y <= 60px`) に直接 `[ ここにドロップして親を解除 (ルートタスク化) ]` エリアを描画。ノードを上部エリアで離すことで範囲外に出ることなく確実にルート化を実行。

### (4) 子要素のルート要素化メカニズム (Subtask-to-Root Elevation)
- インスペクターの `[ ルート化 ]` ボタンまたはキャンバス最上部へのドラッグ＆ドロップで子タスクをルート階層 (`parentId: null`) へ移動。

### (5) GanttProject進化系ガントチャート ＆ 遅延判定・ヘッダー幅完全一致
- **親完了予定日超過の赤表示・遅延日数表示 (Overdue Subtask Red Highlight & Delay Badge)**:
  - 子タスクの完了予定日 (`dueDate`) が親タスクの完了予定日を超過している場合、超えた超過期間のバーを赤いハイライトグラデーションで強調表示し、「`+N日遅延`」の警告バッジを表示。プロジェクトの進行ボトルネックを視覚的に一目で発見可能。
- **ヘッダー幅の完全一致修正 (`gantt-ticks-header` Style Alignment)**:
  - ガントタイムライン上部のヘッダー軸 (`gantt-ticks-header`) のセル幅と、下のグリッドセル (`gantt-bar-cell`) のカラム幅を完全に同一ピクセル幅で同期させ、描画ズレ・スタイル崩れを完全に防止。
- **完了予定日マーカー (`🚩`) の直感的ドラッグ＆ドロップ編集**:
  - ガントチャート上の完了予定日マーカー (`🚩`) をマウスで掴んで左右にスライド（ドラッグ）することで、直感的に完了予定日 (`dueDate`) を変更・即座に自動保存・同期。
- **最長完了予定日の全領域自動スケール (Auto-Fit Range)**:
  - プロジェクト内の全タスクの中で一番遠い完了予定日 (`dueDate`) を自動判定し、タイムライン右端内にマーカーやバーが完全に収まるようスケールを自動調整。

### (7) 外部データファイル改変自動検知・リアルタイム反映機能 (External Data Modification Live Watcher & Reload)
- **外部変更の自動追従**: 共有ドライブ（Dropbox / NAS / 共有フォルダ等）や Git 操作、他ツール・別プロセス等によってデータ保存ディレクトリ (`data/`) 内の `events.jsonl` や `state.json` が直接追記・編集・置換された場合を自動で検知。
- **ノンストップ同期 ＆ ホットリロード**: アプリを再起動したり画面をリロードすることなく、追記された未知のイベントログを即座に自動読込（ID重複排除）し、最新状態スナップショットを再生成して WebSocket 経由で前面グラフビューおよびガントチャートへ即座にリアルタイム更新反映。

## 2. データ保存・共有ディレクトリ仕様 (ターミナル目線 絶対パス構造)
- **通常可視フォルダによる保存・共有運用 (`data/`)**:
  - タスク状態スナップショット (`state.json`) およびイベントログ (`events.jsonl`) は、デフォルトでターミナル目線で把握・アクセスしやすい標準フォルダ **`data/`**（絶対パス `path.resolve(process.cwd(), 'data')`）で管理されます。
  - 複数端末・複数プロセスでの共有時、`config.json` や CLI オプション `--data-dir` にて共有ドライブや任意フォルダの **絶対パス**（例: `/Users/.../WBSer/data`）を指定することで同一データをリアルタイム同期。
  - 単一バイナリパッケージング（`pkg`）時、初期マスターデータはバイナリの VFS (`/snapshot/...`) 内に埋め込み参照（Read-Only）し、実行時の動的データ変更は外部の絶対パス指定ストレージへ安全に永続化。
  - 既存の `./.wbser_data` ディレクトリが存在する場合は自動検出して読み込むフォールバック互換性も保持。

## 3. 解決する課題
- **全体像と構造化の可視性**: 全体が俯瞰できる前面グラフビュー（最上部焦点移動・親ナビゲーションUI）と、遅延チェック機能付きの時系列ガントチャートにより多角的にタスク状況を把握。
- **誤操作防止 ＆ 履歴追跡性**: 端末単位Undo機能、進行中予定日必須化、3子要素以上削除理由10文字以上ログ記録、および隠しディレクトリ保護により、データの保全性と変更追跡性を飛躍的に向上。
- **外部データ変更へのシームレス追従**: 外部ファイル操作や他ツール・共有ドライブ同期時にも、アプリを起動したままリアルタイムに最新のタスク構造・進捗状況を自動反映。
- **柔軟な運用形態**: 分散P2P・クライアント接続・ホスト運用の3モードを自由に切り替え。

---

## 4. 拡張性を担保する原則
- **ローカル優先・非同期伝播**: 変更は常にローカルの `/.wbser_data/state.json` および `.jsonl` ファイルへ即座に記録し、P2Pネットワークへは非同期で波及させる。
- **UI 非依存 Core**: Obsidianグラフキャンバスおよびガントチャートのいずれにも移植できるモジュール構造とする。
