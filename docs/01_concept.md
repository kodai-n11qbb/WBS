# 01. 概念とユースケース

[インデックスへ戻る](./index.md)

---

## 1. 全体概要
本システムは、中央サーバーを必要とせず、同一ローカルエリアネットワーク (LAN) 内に存在する端末同士が直接通信（P2P）することで、プロジェクトの進捗・タスク状態・アクティビティを共有・管理するためのツールです。

**「Local-First（ローカルファースト）」** 設計思想および **「Gitライクな追跡ログ (JSONL Append-Only Log)」** を採用しており、オフライン時でも全変更履歴を含めて安全に閲覧・更新・持ち運びが可能です。

---

## 2. 本システムにおける「構造化」の定義

本ツールでは、手軽なサクサク入力を損なわないよう**属性入力の強制は行わず（目的やDoDは任意のオプション項目）**、主に **タスク間の関係（ツリー構造）** と **変更履歴（GitライクなJSONLログ）** を軸として構造化します。

```
                    +--------------------------------+
                    |        本システムの構造化方針    |
                    +--------------------------------+
                                   |
       +---------------------------+---------------------------+
       |                           |                           |
       v                           v                           v
【柔軟なタスク属性 (Option)】   【1. 関係の構造化 (Tree)】   【2. 履歴の構造化 (Log)】
・タイトル (必須)              ・親タスク (Parent)          ・Gitライクなイベントハッシュ
・目的・背景 (Why: 任意)       ・子タスク (Subtasks)        ・JSONL 形式での不変ログ
・完了定義 (DoD: 任意)         ・ツリー階層構造             ・全変更/削除の完全追跡
```

### (1) 柔軟なタスク属性 (Flexible Attributes with Options)
- **手軽さと自由度の重視**: タスク作成時は「タイトル」のみのシンプルな入力で即座に登録可能。目的 (Why) や完了定義 (DoD) は必要に応じて後から付加できるオプション項目とします。

### (2) 関係の構造化 (Hierarchical Tree Structuring)
- **ツリー構造 (Parent-Child Task Tree)**: 大目標（親タスク）から中タスク・子タスク（サブタスク）へと階層状に分解して可視化・管理できます。

### (3) 履歴の構造化 (Git-like Audit Log)
- **Git型変更追跡 (JSONL Append-Only)**: 各操作（作成・変更・移動・削除）を Git コミットのように改ざん不能な不変イベントログとして `.jsonl` ファイルに1行ずつ追記。誰がいつ何を変更したかを100%追跡可能。

---

## 3. 解決する課題
- **手軽なタスク登録**: 必須入力をタイトルのみにし、思考を邪魔せず即座にタスクを作成。
- **複雑なプロジェクトの階層分解**: ツリー構造により、大きな作業を小さな実行単位へ柔軟に分解。
- **履歴追跡と抜群のポータビリティ**: Gitのような全履歴ログを JSONL ファイル1本でポータブルに保管・移動可能。
- **ゴースト防止型分散削除 (Tombstone Pattern)**: P2P環境で削除イベントを不変ログとして伝播し、他端末での誤復活を防ぐ。
- **直感的なWeb/GUI操作 (Drag & Drop)**: カンバン画面上でドラッグ＆ドロップによる階層移動・状態変更・並び替え。

---

## 4. 拡張性を担保する原則
- **ローカル優先・非同期伝播**: 変更は常にローカルの `.jsonl` ファイルへ即座に記録し、P2Pネットワークへは非同期で波及させる。
- **トランスポート透過性**: P2P 通信が UDP/TCP/WebSockets/WebRTC のいずれであっても、進行管理のドメインロジックに影響を与えない設計とする。
- **UI 非依存**: CLI、Web UI、ネストツリー表示、ネイティブデスクトップ枠（Tauri/Electron等）のいずれにも移植できる構造とする。
