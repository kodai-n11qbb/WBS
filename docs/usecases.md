## 1. 想定利用シナリオ

### シナリオA: 個人エンジニアによるオフライン思考・WBS整理
- **背景**: インターネット接続のない出張中や飛行機内、または社内セキュア環境。
- **行動**:
  1. `npm run dev` または単一バイナリを起動。
  2. 画面下部のプロンプトバーからプロジェクトの主要タスクを入力。
  3. グラフキャンバス上でタスク同士をドラッグ＆ドロップして親子関係（WBS）を階層化。
  4. 着手するタスクを `IN_PROGRESS` に変更し、ポップアップで完了予定日を入力。
  5. ガントチャートビューに切り替え、全体のスケジュール感とボトルネックを確認。

### シナリオB: 小規模チームによるLAN内P2Pリアルタイム協業
- **背景**: 社内オフィスLAN内で3〜5名のエンジニアチームが同じプロジェクトのWBSを同時進行管理。
- **行動**:
  1. 1名がホストモード（`HOST`）または全員が分散モード（`P2P`）で起動。
  2. UDPブロードキャストにより同一LAN内のノードを自動発見。
  3. タスクの追加・ステータス更新が不可変イベントログ（`events.jsonl`）経由で相互同期。
  4. 誤って別のタスクを完了にしてしまったメンバーが、ヘッダーの「1つ戻す（Undo）」をクリックして自分の直前操作のみを安全に取り消す。

### シナリオC: 共有ストレージ・Git連携による非同期チーム協業
- **背景**: リモートワーク環境で、Dropbox, Google Drive, NAS, または Git 等の共有ディレクトリを介してデータを同期。
- **行動**:
  1. 各自の `config.json` の `dataDir` に共有フォルダのパスを指定（デフォルトは `./WBS_data`）。
  2. メンバーAが外部で `git pull` や共有ドライブ同期により `./WBS_data/events.jsonl` を更新。
  3. メンバーBのWBSerがファイル改変監視（File Watcher）で外部更新を自動検知。
  4. 画面を再読み込みすることなく、前面のグラフビューおよびガントチャートに最新のタスク情報がリアルタイム反映される。

### シナリオD: 役割ごとのWBS自律作成と意思決定確認負荷の削減（スプシ自動共有）
- **背景**:
  エンジニア、デザイナー、PM、ビジネス企画などの複数ロールが参加するプロジェクト。「誰がどこまで進めていて、次に誰が何を判断すべきか」を確認する定例会議やヒアリング、Slackでの状況確認の負荷が大きく、意思決定のボトルネックになっている。
- **行動**:
  1. 各ロールのメンバーが、自分の担当領域でタスクを分解し、WBSツリーとして自由に構造化。
  2. 着手タスクに期日を設定することで、副産物としてタイムラインおよびGoogleスプレッドシートの「WBS」シートへ最新のガント行列（縦軸ツリー×横軸日程）が自動プッシュ送信される。
  3. PMや経営陣・クライアントは使い慣れたスプレッドシートを開くだけで、常に最新の全体進捗と依存関係を把握できる。
  4. 「現状どうなってる？」という確認コミュニケーションが激減し、次の意思決定の議論に即座に入れるようになる。

## 2. 主要ユースケース一覧

```
+-----------------------------------------------------------------------------------+
|                                 WBSer ユースケース                                 |
+-----------------------------------------------------------------------------------+
|  [ユーザー]                                                                       |
|     │                                                                             |
|     ├── (UC-01: タスク作成と親子構造化) ─────────────────> グラフキャンバス配置  |
|     │                                                                             |
|     ├── (UC-02: 進行中ステータス変更と期限設定) ─────────> 日付入力ダイアログ強制 |
|     │                                                                             |
|     ├── (UC-03: 親子完了予定日の整合性検証) ─────────────> ガント赤遅延バッジ表示 |
|     │                                                                             |
|     ├── (UC-04: 重要サブツリーの一括安全削除) ───────────> 10文字理由入力モーダル |
|     │                                                                             |
|     ├── (UC-05: 自端末の直前操作取り消し) ───────────────> 端末単位Undo逆イベント |
|     │                                                                             |
|     ├── (UC-06: 外部データ変更のリアルタイム追従) ───────> Live Watcher自動反映   |
|     │                                                                             |
|     ├── (UC-07: 環境非依存の起動と対話セットアップ) ─────> npm run setup / 単一bin |
|     │                                                                             |
|     └── (UC-08: Googleスプレッドシートへのガント同期) ───> 「WBS」シート自動更新  |
+-----------------------------------------------------------------------------------+
```

### UC-01: タスク作成と親子構造化
- **アクター**: プロジェクト作業者
- **事前条件**: WBSer が起動していること。
- **メインフロー**:
  1. 画面下部のタスク追加バーにタスク名を入力し Enter を押下。
  2. ルートタスクとしてグラフキャンバスに新ノードが物理レイアウト配置される。
  3. 既存の親タスクが存在する場合、プロンプトの親セレクタまたはキャンバス上のドラッグ操作で親子関係を紐付ける。
  4. 末端タスク数に応じた Sugiyama 風アルゴリズムにより、ノード間の線が交差することなく自動整列する。

### UC-02: 進行中ステータス変更と期限設定
- **アクター**: タスク実行者
- **メインフロー**:
  1. インスペクターパネルでステータスを `TODO` から `IN_PROGRESS` に変更する。
  2. システムが `dueDate`（完了予定日）の有無を検証。
  3. `dueDate` が未設定の場合、完了予定日設定ダイアログがモーダル表示される。
  4. ユーザーが日付を選択・決定すると、`TASK_STATUS_UPDATED` イベントが発行され状態が更新される。

### UC-03: 親子完了予定日の整合性検証
- **アクター**: プロジェクト管理者 / メンバー
- **メインフロー**:
  1. ガントチャートビューを開く。
  2. 子タスクの完了予定日が、親タスクの完了予定日より未来（超過）になっている場合をシステムが自動判定。
  3. 子タスクの超過バー期間が赤いグラデーションで強調表示され、「`+N日遅延`」バッジが表示される。
  4. 必要に応じて、ガントチャート上の完了予定日マーカー（🚩）をドラッグして日付を調整する。

### UC-04: 重要サブツリーの一括安全削除
- **アクター**: タスク整理者
- **メインフロー**:
  1. 3つ以上の子要素を持つ親タスクを選択し、削除アクションを実行。
  2. システムが子要素数（>=3）を検知し、削除理由入力モーダルを表示。
  3. ユーザーが10文字以上の正当な理由を入力して承認する。
  4. `reason` が記録された `TASK_DELETED` イベントが発行され、安全に削除される。

### UC-05: 自端末の直前操作取り消し (Undo)
- **アクター**: 誤操作を行った作業者
- **メインフロー**:
  1. ヘッダーバーの `[ ↺ 1つ戻す (Undo) ]` ボタンを押下（またはショートカット）。
  2. システムがイベント履歴を逆走し、現在のノードID（`authorNodeId`）が発行した直近の操作を特定。
  3. その逆操作となる `UNDO_ACTION` イベントを発行し、状態を1手分復元する。

### UC-06: 外部データ変更のリアルタイム追従
- **アクター**: 外部プロセス / 同期ツール / チームメンバー
- **メインフロー**:
  1. 共有ドライブや Git 経由で `./WBS_data/events.jsonl` に新規イベントが追記される。
  2. WBSer の `FileWatcherPort` が変更を自動検知（100〜300ms デバウンス）。
  3. 未取り込みの差分イベントのみを重複排除してメモリへ展開・再集計。
  4. WebSocket経由で前面グラフキャンバスおよびガントチャートへリアルタイム配信され、画面が更新される。

### UC-07: 環境非依存の起動と対話セットアップ
- **アクター**: 初回導入者 / エンジニア / 非エンジニア
- **メインフロー**:
  1. 開発環境では `git clone` → `npm install` → `npm run dev`（または `npm run setup`）を実行。
  2. 一般利用では配布バイナリをダブルクリックするだけで即座にブラウザが起動。
  3. 初回データ未作成時も、本日基準のデモWBSが自動生成されて即座に操作感を試すことができる。

### UC-08: Googleスプレッドシートへの一方通行ガント同期
- **アクター**: プロジェクト管理者 / チーム作業者
- **メインフロー**:
  1. ツールバーの「📊 スプシ連携」ボタンをクリックし、表示されたGASコードをコピーして対象スプレッドシートにデプロイ。
  2. 発行されたウェブアプリURLをモーダルに貼り付けて保存。
  3. WBSer上でタスクの追加・階層変更・ステータス更新・期日変更が行われると、変更検知により3秒後に最新ガント行列（縦軸ツリー×横軸日程）が自動送信される。
  4. スプレッドシート内の「WBS」シートのみが安全に更新され、他シートを汚すことなく外部関係者への共有・進捗確認が常時自動化される。
