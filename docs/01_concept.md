# 01. 概念とユースケース

[インデックスへ戻る](./index.md)

---

## 1. 全体概要
本システムは、中央サーバーを必要としない対等な **分散モード (P2P)**、指定ホストに接続する **クライアントモード (CLIENT)**、および自端末で接続を受け付ける **ホストモード (HOST)** の3つの柔軟な運用形態に対応した、プロジェクト進行管理ツールです。

**「Local-First（ローカルファースト）」** 設計思想、**「前面化された Obsidian型ノードグラフ表示 (Obsidian Graph Canvas View)」**、および **「ディレクトリ直下の最新状態スナップショット (`data/state.json`)」** を採用しており、直感的なビジュアル操作と全体像の一目での把握を実現します。

---

## 2. メインインターフェース設計（Obsidian Graph 前面化 ＆ 最小限ヘッダー）

本ツールでは、全体の構造化と「全体像が見えること」を最優先とし、**Obsidian型ノードグラフ表示を主軸（前面）**に配置した全画面キャンバスを基礎とします。

```
+-----------------------------------------------------------------------------------------+
| [最小限タイトル] [接続ステータス]                                        [最小限ボタン]  |
+-----------------------------------------------------------------------------------------+
|                                                                                         |
|      (親の親 / 祖先ノード)  ← 画面上部へ自然と配置                                        |
|             ◯                                                                           |
|            / \                                                                          |
|           ◯   ◯  (子ノード)  ← 下方向へ自然にぶら下がる                              |
|          /                                                                              |
|         ◯  (孫ノード)                                      [画面端 ネスト表示切替]      |
|                                                            | デフォルト | 数値 | 全部 | |
|                                                                                         |
+-----------------------------------------------------------------------------------------+
|                      画面下部固定 ChatGPT風タスク追加プロンプトバー                       |
|  [📁 ルートタスク ▾]  タスク名を入力してEnter...                               ( ↑ )   |
+-----------------------------------------------------------------------------------------+
```

### (1) 前面化された Obsidian型 物理グラフィカルキャンバス (Obsidian Graph View)
- **前面メイン画面化**: アプリの標準画面としてグラフキャンバスを前面に配置。
- **過度な演出の排除**: ド派手なエフェクトや装飾を廃し、実用的で静かな視覚表現とバネ物理に絞り込み。
- **階層に応じた自然な上下配置（Y軸重力・垂直バイアス）**:
  - 構造の上位（親の親・祖先ノード）であるほど、自然と画面上部へ移動・漂う物理挙動。
  - 子・孫ノードは親ノードの下方向へ自然にぶら下がるため、全体の上下関係と構造が一目で把握可能。

### (2) 画面端のネスト表示深度調整 (Screen Edge Nesting Depth Control)
- 画面端（右側など）に配置されたシンプルな深度切り替えコントローラー。
  - **デフォルト**: 読みやすい主要階層までを表示。
  - **数値指定 (カスタム)**: 任意で表示するネストの深さ（階層数 1, 2, 3...）を指定可能。
  - **すべて表示 (All)**: 全階層のネストを網羅して全画面表示。

### (3) 整理された最小限ヘッダー (Minimalist Header)
- 不要なボタンや余計な情報を削ぎ落とし、最小限のタイトル、ネットワーク接続状態、最低限の操作ボタンのみを配置。

### (4) 画面下部固定 タスク追加プロンプトバー (Bottom Fixed Floating Prompt Bar)
- 画面最下部に固定表示されるプロンプトバー。
- 直感的なタスク入力と、親未指定時の独立ルートタスク生成に対応。

## 3. ディレクトリ直下の最新状態スナップショット運用 (`data/state.json`) ＆ 動作モード
- **最新状態スナップショット (`data/state.json`)**:
  - タスクの追加・変更・削除のたびに、指定ディレクトリ内の `data/state.json` に最新の全タスク状態（Materialized Snapshot）がリアルタイム自動保存されます。
- **動作モードとアドレス設定**:
  - **`P2P` (分散モード)**: 共有データのアドレス（`data/state.json` のパス）を指定して分散動作。
  - **`CLIENT` (クライアントモード)**: 接続先ホストの端末アドレス（IP/ポート）を指定して接続。
  - **`HOST` (ホストモード)**: 自身を親機として起動しクライアント接続を受付。

---

## 4. 解決する課題
- **全体像と構造化の可視性**: 全体が俯瞰できる前面グラフビューにより、複雑なタスクの繋がりと全体像を一目で整理・把握。
- **柔軟な運用形態**: 分散P2P・クライアント接続・ホスト運用の3モードを自由に切り替え。
- **ポータブルなデスクトップバイナリ配布**: Node.js/Python 等が入っていない環境でも、単一バイナリ (`.exe` / `.app`) をダブルクリックするだけで即時起動。

---

## 5. 拡張性を担保する原則
- **ローカル優先・非同期伝播**: 変更は常にローカルの `data/state.json` および `.jsonl` ファイルへ即座に記録し、P2Pネットワークへは非同期で波及させる。
- **UI 非依存 Core**: Obsidianグラフキャンバス、ツリー、他表現のいずれにも移植できるモジュール構造とする。
