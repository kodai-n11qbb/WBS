## 1. 動作モード (Operating Modes)

利用環境や運用形態に合わせて、以下の3つのモードを選択可能です。

| モード名 | 端末のアドレス (`hostAddress`) | データ保存先 (`dataDir`) | 動作概要 |
| :--- | :--- | :--- | :--- |
| **`P2P`** (分散モード) | **不要** (UDP自動発見) | **要指定** (`data/` 等) | LAN内の仲間や共有フォルダ経由で対等に同期 |
| **`CLIENT`** (クライアントモード) | **要指定** (`192.168.1.50:3000`) | **不要** (ホスト側で保存) | 指定したホスト親機に接続して利用 |
| **`HOST`** (ホストモード) | **不要** (自身が親機) | **要指定** (`data/` 等) | 自端末をホスト親機として起動し接続受付 |

## 2. イベントログ同期と重複排除 (Deduplication)

```
[Node A] ── Event 発行 ──> data/events.jsonl 追記 ──> UDP/WS 送信
                                                         │
                                                         v
[Node B] <── イベント受信 <──────────────────────────────┘
   │
   ├── 1. イベントID（UUID）の既存チェック
   │      └── すでに適用済みならスキップ (重複排除)
   ├── 2. 未知のイベントならメモリ内タスクツリーへ適用
   └── 3. ./WBS_data/events.jsonl への安全追記 ＆ UI反映
```

1. **不可変イベントの伝播**: すべてのアクションは UUID 付きの `SyncEvent` としてシリアライズされます。
2. **重複排除**: 各ノードは受信したイベントの `id` をキーとしてメモリ内イベントマップと照合し、すでに処理済みのイベントは二重適用せずに破棄します。
3. **最終書き込み優先 (Last-Write-Wins)**: 同一タスクの同一プロパティに対する並行競合は、イベントの `timestamp` に基づいて自動調停されます。

## 3. 外部データファイル改変検知・再同期 (Live Watcher & Hot Reload)

外部ツールや Git 操作（`git pull`）、クラウドストレージ（Dropbox, NAS）の同期によって `./WBS_data/events.jsonl` や `./WBS_data/state.json` が直接変更された場合、アプリ再起動なしで自動反映されます。

```
+-----------------------------------------------------------------------------------------+
|                  外部ファイル改変監視 ＆ ホットリロード シーケンス                       |
+-----------------------------------------------------------------------------------------+
| 1. [FileWatcher] OSファイルシステムイベント検知 (fs.watch / 100~300ms デバウンス)      |
|                                     │                                                   |
|                                     v                                                   |
| 2. [Repository] 差分読み込み ＆ イベントID重複排除 (Delta Read & Deduplication)         |
|                                     │                                                   |
|                                     v                                                   |
| 3. [NodeService] ドメイン状態再集約 ＆ state.json スナップショット更新                   |
|                                     │                                                   |
|                                     v                                                   |
| 4. [WebSocket] STATE_UPDATED を全クライアントへブロードキャスト (UI即座最新化)           |
+-----------------------------------------------------------------------------------------+
```

1. **検知 (Detection)**: `FileWatcherPort` が `data/` 配下のファイル更新イベントを検知。OSの一時ロックやマルチ発火をデバウンス（150ms）で吸収。
2. **差分読込 (Delta Read)**: `events.jsonl` から新規行を抽出し、メモリ内の既存イベントIDと照合して未取得のイベントのみを取り込む。
3. **ドメイン再集約 (Reconciliation)**: `SyncEngine` が差分イベントをタスクツリーに適用し、最新の `state.json` を更新。
4. **UI反映 (Broadcast)**: WebSocketを通じて接続中のフロントエンドへ `STATE_UPDATED` を通知。グラフおよびガントチャートがリロードなしで即座に再描画。

## 4. 端末単位 Undo (1つ戻す) メカニズム

```
[イベント履歴 (新しい順)]
  [3] Node B: TASK_TITLE_UPDATED  <-- 他メンバーの操作 (スキップ)
  [2] Node A: TASK_STATUS_UPDATED <-- 自端末(Node A)の直前操作 (ターゲット特定!)
  [1] Node A: TASK_CREATED
```

1. **自端末イベントの探索**: 自ノードID（`authorNodeId`）が発行した有効なイベントを、最新から過去へ向かって逆順スキャン。
2. **逆操作イベント (`UNDO_ACTION`) の発行**:
   - 例: 直前操作が「ステータスを DONE に変更」だった場合、「ステータスを直前の状態（IN_PROGRESS等）に戻す」打ち消しイベントを発行。
3. **他メンバーへの影響ゼロ**: 全体の履歴を巻き戻す（ロールバックする）のではなく、逆操作のイベントを末尾に追加するため、他の参加者の作業を破壊しません。
