# 1.1 プロジェクト概要・コンセプト (concept.md)

[ドキュメントインデックスへ戻る](./index.md)

---

## 1. プロジェクト目的

**WBSer（ダブリュービーサー）** は、ローカルファースト（Local-First）思想に基づいて設計された、分散 P2P / ホスト / クライアント対応のプロジェクト進行・WBS（Work Breakdown Structure）タスク管理システムです。

中央集権的なクラウドサーバーや外部SaaSへの常時接続を前提とせず、個人PCのローカル環境で軽快に動作しつつ、同一LAN内の同僚や共有フォルダ経由での共同作業をシームレスに実現します。

---

## 2. 解決する課題

1. **ツリーと時系列の断絶**:
   - 従来のWBSツールやタスク管理ツール（Jira, Trello, Asana等）はカンバンやリストが中心であり、プロジェクト全体の親子階層構造や依存関係を直感的に俯瞰しにくい。
   - 逆に従来のガントチャート専用ツール（Microsoft Project, GanttProject等）は入力・更新が重厚で、思考の初期段階での発想や柔軟なツリー組み換えに適していない。
2. **クラウド依存とオフライン不耐性**:
   - ネットワーク遮断時やセキュリティ制限の厳しいイントラネット環境（社内LAN、工場、機密環境等）で利用できない。
3. **データ誤操作・破壊への脆弱性**:
   - 共有環境で誰かが誤ってツリー配下の重要タスクを一括削除してしまったり、誤ったステータス更新を行って戻せなくなるリスク。
4. **外部ツール・共有ドライブとの連携分断**:
   - 共有ドライブ（Dropbox, NAS, Git共有）でデータファイルを直接操作したり同期した際に、ツールを再起動しないと変更が反映されない。

## 3. コアコンセプト ＆ 差別化ポイント

### (1) Obsidian型ノードグラフ前面配置 ＆ GanttProjectスタイルガントチャートの2ビュー特化
- 従来のツリービュー・カンバンビューを廃止し、**「全体の構造化（グラフ）」** と **「時系列の整合性（ガント）」** の2つの主要ビューに特化。
- **グラフビュー**: Obsidianのグラフビューのように思考を広げ、タスクの親子関係を物理バネ演算（Spring Physics）と Sugiyama風レイヤード配置で可視化。
- **ガントチャート**: 完了予定日と進捗ステータスから不完全作業期間を自動プロットし、親要素の完了予定日を超過した子タスクを赤色ハイライト・遅延バッジ表示。

### (2) Local-First（ローカルファースト）
- すべての変更アクションはまずローカルストレージ（`data/state.json` および `data/events.jsonl`）にミリ秒単位で即座に永続化。
- ネットワーク通信は非同期で波及し、オフライン時でも全機能が完全に動作。

### (3) 柔軟な3つの動作モード (P2P / CLIENT / HOST)
- **P2P（分散モード）**: 中央サーバー不要。同一LAN内のUDP自動発見または共有データディレクトリ経由で対等同期。
- **CLIENT（クライアントモード）**: 特定の親機ホスト端末へ接続して利用。
- **HOST（ホストモード）**: 自端末をホスト親機として起動し、他メンバーからの接続を受付。

### (4) 堅牢なデータ保護メカニズム
- **端末単位 Undo（1つ戻す）**: 他メンバーの作業を巻き込まず、自端末（`authorNodeId`）が行った直前アクションのみを安全に取り消す逆操作イベントを発行。
- **進行中（IN_PROGRESS）ステータス時の完了予定日必須化**: 日付のない作業着手を防ぎ、ガントチャートの破綻を未然に防止。
- **3子要素以上削除時の理由ログ必須化**: 影響の大きいツリー削除時に10文字以上の理由入力を義務付け、イベントログに恒久記録。

### (5) 外部データファイル改変自動検知 ＆ リアルタイム反映 (Live Watcher)
- OSのファイルシステム監視（`fs.watch` / Polling）により、外部プロセスや共有ドライブ同期による `events.jsonl` / `state.json` の変更を自動検知。
- アプリを再起動することなく、リアルタイムに画面を自動更新（ホットリロード）。

## 4. 設計・開発の基本原則

- **Clean / Hexagonal Architecture**: コアビジネスロジックはフレームワークやOS、プロトコルから完全に独立し、ポート＆アダプターを通じて疎結合に連携。
- **Rule of Three**: 共通化・抽象化は3回以上類似コードが出現するまで行わない（YAGNI徹底）。
- **Dependency Injection**: 具象クラスの直接生成を避け、外部から注入可能な設計とする。
- **単一バイナリ配布**: Node.js等のランタイム環境が未導入の一般PCでも、ダブルクリックだけで即時起動可能なネイティブ実行バイナリを提供。
