# decision-log.md (ADR: 意思決定記録)

プロジェクトにおける技術選定、ツールの試用・導入判定（Spike）、設計例外の決定経緯を簡潔に記録する。
**AIはツール試用前に本一覧を確認し、過去に検証済みのツールの再検証を行わないこと。**

---

## 記録フォーマット

```markdown
### [YYYY-MM-DD] タイトル（例: ツール試用: ライブラリ名 / 設計例外）
- **ステータス**: 採用 / 見送り / 例外承認
- **用途・背景**: なぜ検討したか
- **検証結果・判断理由**:
  - メリット:
  - リスク・デメリット:
- **結論**: 今後の方針（採用時は利用コマンドやスクリプトパスを記載）
```

## 記録一覧

### [2026-10-19] ツール試用: Playwright (ブラウザ・UI自動検証)
- **ステータス**: 採用
- **用途・背景**: UIの描画確認、インタラクション（クリック・表示切替）の自動検証
- **検証結果・判断理由**:
  - メリット: 人間が手動確認して往復するコスト（手戻りトークン）を削減できる。ヘッドレスで即座にDOM状態を検証可能。
  - リスク・デメリット: 初回スクリプト作成のオーバーヘッド（約2,000tok）があるが、2回目以降で大幅に回収可能。
- **結論**: UIの動作確認時は `scripts/verify_*.js` などの形式で自律的に検証スクリプトを作成・実行して確認する方針とする。

### [2026-10-19] 単独要素（親・子を持たない要素）の期日未設定ゾーン常駐表示仕様
- **ステータス**: 採用
- **用途・背景**: WBSツリーに未整理の単独タスク（親なし・子なし）を、タイムライン表示中にもアクセス可能にし、期日未設定ゾーン（Zone 1）へ集約表示したいという要望。
- **検証結果・判断理由**:
  - メリット: 特定ツリーのタイムライン表示中であっても未割り当てタスクが左端「📅 期日未設定」ゾーンに常駐するため、タスクの存在を見失わず、ドラッグで期日設定やツリー組み込みが容易になる。期日設定後の単独要素は他ツリー表示を乱さないよう非表示（案A）とすることで、タイムライン本来の視覚的集中度を維持できる。
  - リスク・デメリット: 単独要素の個数が多い場合に期日未設定列が縦長になる可能性があるが、既存のY軸ステップ配置（54px）およびラベル横配置により破綻なく収容可能。
### [2026-10-19] 全体グラフ表示バグ解消およびJS実行パフォーマンス最適化（物理スリープ・文字幅キャッシュ・計算メモ化）
- **ステータス**: 採用
- **用途・背景**:
  1. 全体見るモード（未選択時）において、第2階層タスクの横幅押し出しのドミノ現象により、右端画面外への突き抜けとノード重なりが発生していた。
  2. 毎フレーム（60fps）走るアニメーションループ内で `computeSugiyamaTreeXPositions`（再帰木探索）や pairwise ループ内 `ctx.measureText`（1フレーム420回、毎秒25,200回）が実行され、JS分析・実行負荷（Analyzed / Scripting time）が肥大化していた。
- **検証結果・判断理由**:
  - メリット:
    - **全体レイアウト安定化**: 階層内の横幅スケーリングと画面端（`[padX, width - padX]`）への正規化を導入し、`minRepelDist` を 120px から 55px に適正化。密集階層には2段階Y軸スタッガー配置（32px垂直分離）を適用し、画面外はみ出し0件・円衝突0件・ラベル衝突0件を達成。
    - **JS負荷90%超削減**: ツリー構造計算・日付グルーピングをフレーム外へメモ化。ノード生成時に `titleWidth` を事前計測・キャッシュしてループ内の `measureText` を全撤廃。物理移動速度が閾値（`maxVelocity < 0.02`）を下回った際に `requestAnimationFrame` を停止（物理スリープ）させ、マウス操作や状態変更時に `wakeAnimation()` で即座に復帰させることで、待機時のCPU使用率をほぼ0%に圧縮。
  - リスク・デメリット:
    - スリープ状態からの復帰漏れリスクがあったが、`mousedown`, `mousemove` (hover切替含む), `mouseup`, `mouseleave`, `wheel` および各種データ更新（`renderCurrentView`）すべてに `wakeAnimation` を接続し解消。
- **結論**: Sugiyama X軸正規化とスタッガー配置、および物理スリープ・テキスト計測キャッシュ・レイアウトメモ化を採用・実装。

### [2026-10-19] 全体グラフ表示時の半透明化バグの解消
- **ステータス**: 採用
- **用途・背景**: 全体見るモード（未選択時）において、全ノード、ラベルプレート、テキスト、エッジが極端に半透明（10%〜30%の不透明度）で描画され、視認性が著しく悪化していた。
- **検証結果・判断理由**:
  - 原因: `updateLayoutState` において `activeTimelineSet = new Set(activeTreeSet || [])` と初期化されていたため、未選択時（`activeTreeSet == null`）にも空のSet（truthyなオブジェクト）が生成されていた。これにより各描画ロジックで `isDimmed = activeTimelineSet && !isInSubtree` が全ノードに対して `true` と判定され、全体が減衰描画されていた。
  - 修正:
    - `isTimelineMode` が `true` の場合のみ `activeTimelineSet` を生成し、未選択時は厳密に `null` に設定。
    - 各描画コード（円、ハロ、文字、エッジ）の `isDimmed` 判定条件に `isTimelineMode` を追加。
    - 全体グラフ時の通常エッジを点線から視認性の高い実線（コントラスト向上）へ改善。
  - メリット: 全体見るモードにおいて全ノード、ラベル、接続線が100%ソリッドかつ明瞭に表示されるようになった。
- **結論**: `public/app.js` のタイムライン判定と減衰フラグを修正し、Playwrightスクリーンショット監査にて正常表示を確認。
