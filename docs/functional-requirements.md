## 1. 機能要件サマリー (Must / Should / Want 分類)

本ドキュメントでは、WBSerの提供する機能要件を優先度（Must / Should / Want）別に分類・定義します。

- **Must (必須)**: コア機能。これがないと製品として成立しない。
- **Should (重要)**: ユーザビリティや協業性・耐障害性のために必須級の機能。
- **Want (任意・次期検討)**: さらなる利便性向上のための発展機能。

## 2. 機能要件一覧

### (1) 画面 ＆ UI プレゼンテーション機能

| ID | 機能名 | 分類 | 詳細要件 |
| :--- | :--- | :--- | :--- |
| **FR-UI-01** | 100vh 全画面特化 Obsidianグラフキャンバス | **Must** | 画面スクロールを廃止し、`100vh` 全画面を最大限に活用した Obsidian型物理グラフキャンバスに完全特化。上部統合ツールバー・キャンバス・ドック型インスペクター・下部タスク入力バーの4層構成とすること。 |
| **FR-UI-02** | Obsidian型 物理ノードグラフ描画 | **Must** | HTML Canvas を用い、タスクをノード、親子関係を接続線としてバネ物理シミュレーションと階層重力により有機的に描画すること。 |
| **FR-UI-03** | Sugiyama風 レイヤードツリー自動整列 ＆ フォーカス時横幅自動ワイド展開 | **Must** | 親子ツリーの末端タスク数（Leaf Count）を再帰計算し、サブツリー同士のX座標領域を非交差に配置して線の絡まりを防止すること。さらに、ノード選択（フォーカス）時は縦方向（Y軸）だけでなく、選択サブツリー配下の子要素群に対してキャンバス有効横幅（X軸）全体を均等再分配し、親ノードを水平中央に配置してワイドに展開すること。 |
| **FR-UI-04** | ネスト数に応じた縦方向自動スケール | **Must** | 表示対象タスクの最大階層数（1〜N）に応じてキャンバスのY軸高さを自動均等分割すること。 |
| **FR-UI-05** | ノードダブルクリックによるサブツリー限定表示 | **Must** | ノードをダブルクリックした際、クリック要素を最上部頂点とし、上方向に親リンク線を延伸描画しつつ、配下の子孫タスク群のみに絞り込んで描画すること。 |
| **FR-UI-06** | 相対ネスト階層フィルタリング | **Should** | 画面端のネスト表示切替（1階層 \| 2階層 \| 3階層 \| すべて）が、要素未選択時は全体（ルート起点）、要素選択時は「クリックされた要素を起点」とした相対階層数として適用されること。 |
| **FR-UI-07** | [廃止] 左上固定 親ナビゲーションUI | **不要** | UIのシンプル化および全画面キャンバスの視界確保のため廃止。 |
| **FR-UI-08** | ドック型インスペクター | **Must** | 詳細インスペクターパネルをタスク入力バーの直上にドック（Dock）配置し、キャンバス上のノードや接続線に覆い被さることなく操作可能とすること。 |
| **FR-UI-09** | キャンバス内最上部 ルート化ドロップゾーン | **Must** | ノードをドラッグ中、キャンバス最上部（`Y <= 60px`）にドロップゾーンを表示し、ドロップで親を解除（ルートタスク化）できること。 |
| **FR-UI-10** | キャンバス空白部クリックによる選択解除 | **Should** | ノード以外のキャンバス空白部分をクリックした際、フォーカス・選択状態を安全に解除し全体表示に戻ること。 |
| **FR-UI-11** | 文字サイズ選択機能 | **Should** | 画面コントローラーからフォントサイズ（小 / 中 / 大）を即座に切り替えられること。 |
| **FR-UI-12** | [統合廃止] ガントチャートビュー群 | **不要** | タイムライン機能をすべて Obsidianグラフビューのタイムラインモードに統合したため廃止。 |
| **FR-UI-16** | テーマ切替 (Dark / Light) | **Should** | 上部統合ツールバーの切り替えスイッチからダークモードとライトモードを瞬時に切り替えられること。 |
| **FR-UI-17** | 要素選択時 サブツリー日付軸タイムライン ＆ 過去日ダイナミック配置 | **Must** | 要素選択時、選択サブツリーのみを表示（非選択ノードは完全非表示）。今日を起点とする日付軸上に完了予定日（`dueDate`）に応じて物理吸着マッピングし、表示範囲内の過去タスクはその日付列に配置、表示範囲外の古いタスクのみ「◀ 過去」ゾーンに集約すること。 |
| **FR-UI-18** | 自動リサイズ同期 (ResizeObserver) | **Must** | ウィンドウやコンテナのサイズ変更を自動検知し、クリック等の操作を挟まず即座にキャンバスの幅・高さを同期調整すること。 |

### (2) タスク管理 ＆ データ整合性・保護機能

| ID | 機能名 | 分類 | 詳細要件 |
| :--- | :--- | :--- | :--- |
| **FR-DATA-01** | タスクの作成・編集・削除 | **Must** | タイトル、親タスクID、ステータス（TODO / IN_PROGRESS / DONE）、完了予定日、表示順序の基本プロパティを管理できること。 |
| **FR-DATA-02** | 進行中 (IN_PROGRESS) 時の完了予定日必須化 | **Must** | ステータスを `IN_PROGRESS` に切り替える際、完了予定日（`dueDate`）の入力を必須とし、未設定時はダイアログを自動表示して入力を強制すること。 |
| **FR-DATA-03** | 3子要素以上削除時の理由ログ必須化 | **Must** | 3つ以上の子要素を持つ親タスクを削除する際、10文字以上の削除理由入力を求め、`TASK_DELETED` イベントの `reason` プロパティへ恒久記録すること。 |
| **FR-DATA-04** | 端末単位 Undo (1つ戻す) 機能 | **Must** | 自端末（`authorNodeId`）が発行した直前の有効アクションを逆走探索し、その逆操作イベント（`UNDO_ACTION`）を発行して直前の状態に安全復元できること。 |
| **FR-DATA-05** | 不可変イベントログ永続化 (`events.jsonl`) | **Must** | すべての状態変更を1行1JSON形式で `data/events.jsonl` に追記保存すること。 |
| **FR-DATA-06** | 状態スナップショット永続化 (`state.json`) | **Must** | イベント集約後の最新タスクツリー状態を `data/state.json` にアトミックに書き出すこと。 |
| **FR-DATA-07** | 保存パスの絶対パス解決 ＆ 旧フォルダ互換 | **Must** | カレントディレクトリ基準の絶対パス（`path.resolve`）で保存先を管理し、既存の `./.wbser_data/` が存在する場合は自動フォールバック検出すること。 |

### (3) 同期 ＆ 外部ファイル改変監視機能

| ID | 機能名 | 分類 | 詳細要件 |
| :--- | :--- | :--- | :--- |
| **FR-SYNC-01** | 3つの動作モード切替 (P2P / CLIENT / HOST) | **Must** | `config.json` または起動オプションにより、分散モード、クライアントモード、ホストモードのいずれかで動作できること。 |
| **FR-SYNC-02** | P2P LAN内自動発見 (UDP Broadcast) | **Must** | P2Pモード起動時、同一サブネット内の他ノードをUDPブロードキャストにより自動探索・接続すること。 |
| **FR-SYNC-03** | 外部データファイル改変自動検知 (Live Watcher) | **Must** | 外部ツールや共有ドライブ、Git操作等によって `events.jsonl` や `state.json` が変更された場合、OSのFSイベント等により自動検知すること。 |
| **FR-SYNC-04** | 差分イベント読込 ＆ 重複排除 | **Must** | 外部で追記されたイベントログから未取得の差分のみを読み出し、イベントIDにより重複をスキップしてメモリ状態へ統合すること。 |
| **FR-SYNC-05** | UIホットリロード (WebSocket ブロードキャスト) | **Must** | 外部変更検知およびドメイン更新後、WebSocketを通じて接続中の全画面へ通知し、ブラウザリロードなしで画面を即時最新化すること。 |
| **FR-SYNC-06** | 監視方式の自動フォールバック | **Should** | OSイベント（`fs.watch`）が機能しないネットワークドライブ環境等において、タイムスタンプ比較による周期ポーリング（`PollingFileWatcherAdapter`）へフォールバックできること。 |

### (4) 配布 ＆ セットアップ機能

| ID | 機能名 | 分類 | 詳細要件 |
| :--- | :--- | :--- | :--- |
| **FR-PKG-01** | 単一バイナリ実行 | **Must** | Node.js非導入環境でも、Windows用 `.exe` および macOS用実行バイナリをダブルクリックするだけで即時Webサーバーが立ち上がりブラウザが開くこと。 |
| **FR-PKG-02** | 対話型セットアップCLI (`npm run setup`) | **Should** | ターミナルから質問に答えるだけで `config.json` を生成し、設定済みバイナリを出力できること。 |
| **FR-PKG-03** | CLI引数による設定オーバライド | **Should** | 起動時に `--port`, `--data-dir` 等の引数を渡すことで、`config.json` の設定値を動的に上書きできること。 |
