## 1. コアドメイン用語

| 用語 | 英語表記 | 定義・説明 |
| :--- | :--- | :--- |
| **Local-First** | Local-First | データの正本（Primary）を常にローカル端末に保持し、オフラインでも完全に動作した上で、他端末と非同期・分散同期する設計思想。 |
| **タスク** | Task | 本システムで管理される最小単位の作業項目。ID、タイトル、親ID、ステータス、完了予定日等の属性を持つ。 |
| **WBS** | Work Breakdown Structure | プロジェクト全体のスコープを細分化した階層型親子構造。 |
| **イベント** | Event | タスクの作成・編集・削除など、状態を変更した事実を表す不可変データ。`events.jsonl` に追記記録される。 |
| **スナップショット** | State Snapshot | 全イベントを最初から再生・集約した結果得られる、ある時点での全タスクの最新状態。`state.json` に出力される。 |
| **ノードID** | Node ID (`authorNodeId`) | 各実行端末（またはユーザー）に割り当てられる一意の識別文字列。Undo機能や更新競合解決の基準となる。 |
| **端末単位Undo** | Node-Local Undo | 他ノードの作業に影響を与えることなく、自ノードが実行した直近の操作のみを安全に取り消す仕組み。 |

## 2. ネットワーク ＆ 動作モード用語

| 用語 | 英語表記 | 定義・説明 |
| :--- | :--- | :--- |
| **分散モード (P2P)** | P2P Mode | 中央サーバーを介さず、LAN内のUDP自動発見または共通データディレクトリを共有して端末同士が対等に同期する運用モード。 |
| **クライアントモード** | CLIENT Mode | 自身はデータ永続化やサーバー機能を持たず、指定された親機（HOST）のIPアドレス・ポートへ接続するモード。 |
| **ホストモード** | HOST Mode | 自端末が親機サーバーとなり、データの永続化を行いながら他クライアントからの接続を受け付けるモード。 |
| **ピア探索** | Peer Discovery | LAN内でWBSerを起動している他の端末をUDPブロードキャスト等を用いて自動発見するプロセス。 |

## 3. UI / プレゼンテーション用語

| 用語 | 英語表記 | 定義・説明 |
| :--- | :--- | :--- |
| **Obsidian型グラフビュー** | Obsidian-Style Graph View | ノードを円（またはバブル）、親子依存関係を接続線とし、バネ物理演算（Spring Physics）を用いて有機的・階層的に描画するキャンバス。 |
| **サブツリーフォーカス表示** | Subtree Focus View | 特定ノードをダブルクリックした際、そのノードを最上部頂点とし、その配下の子孫タスク群のみを画面に絞り込んで表示するモード。 |
| **親ナビゲーションUI** | Parent Navigation UI | キャンバス左上に固定配置（`.graph-parent-nav`）され、現在フォーカスしているノードの親タスクへワンタップで視点移動できるUI。 |
| **インスペクターシールド** | Inspector Shielding | ノード選択時に展開される詳細パネル（ドロワー）が、背後のノードや接続線と視覚的に干渉・重なり合うのを防ぐ物理反発領域およびZ-index保護機構。 |
| **ルート化ドロップゾーン** | In-Canvas Root Zone | ノードドラッグ時にキャンバス最上部（`Y <= 60px`）に出現する、親要素を解除してルートタスクへ昇格させるためのドロップ可能領域。 |
| **Sugiyama風レイアウト** | Sugiyama Untangled Tree Layout | 末端タスク数を再帰的に計算し、X座標の占有幅を自動分配することで接続線の交差を幾何学的に排除する配置アルゴリズム。 |
| **遅延バッジ** | Overdue Delay Badge | 親タスクの完了予定日を超過している子タスクに対して、超過期間を赤色グラデーションで示し「`+N日遅延`」と警告表示するUI。 |

## 4. アーキテクチャ ＆ ストレージ用語

| 用語 | 英語表記 | 定義・説明 |
| :--- | :--- | :--- |
| **ヘキサゴナルアーキテクチャ** | Hexagonal Architecture | ビジネスロジックを中心に据え、外部環境（UI、DB、ネットワーク）とポート（インターフェース）およびアダプターで疎結合に分離する設計様式。 |
| **ファイルウォッチャー** | File Watcher | OSのファイルシステムイベントを監視し、外部による `events.jsonl` や `state.json` の変更を検知して通知するモジュール。 |
| **ホットリロード** | Hot Reload / Live Sync | 外部ファイル変更を検知した際、ブラウザの再読み込みなしでWebSocket経由で画面表示を即時更新する仕組み。 |
| **単一バイナリパッケージング** | Standalone Executable Packaging | Node.jsランタイムとビルド成果物を1つの実行ファイル（`.exe` / macOSバイナリ）に同封し、環境構築不要で動作させる配布形式。 |
