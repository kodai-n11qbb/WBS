# プロジェクトドキュメントインデックス

> 方針: 必要最低限から始め、実装・検証の過程で「これがないと進まない」と判断したものを随時追加する。
> この index.md が全ドキュメントの唯一のマスター一覧である。
> プロジェクトの規模・性質（Webアプリ / モバイルアプリ / CLIツール / ライブラリ 等）に応じて行を取捨選択して使う。

---

## 凡例

| 記号 | 意味 |
|------|------|
| ★★★★★ | リリース・実装ブロッカー。これがないと進行が止まる。 |
| ★★★★☆ | 重要。ないと品質・保守性・チーム認識が著しく損なわれる。 |
| ★★★☆☆ | あると良い。チーム拡大・外注・長期保守に効く。 |
| ★★☆☆☆ | 補助的。状況が変わったら作る。 |
| ★☆☆☆☆ | 理想論。余裕があれば。 |

| ステータス | 意味 |
|-----------|------|
| `未作成` | まだ書いていない。必要になったタイミングで着手。 |
| `草案` | 箇条書き・仮置き。実装進行中にブラッシュアップ。 |
| `確定` | レビュー済み。実装・テストの根拠となる。 |
| `凍結` | 現バージョンでは変更しない。次期検討。 |
| `不要` | このプロジェクトでは不要と判断。理由を備考に記載。 |

## 使い方
### AIエージェント運用について
1. この index.md の更新・ステータス管理は `DEV_POLICY.md` に定めるフェーズ遷移ルールに準拠すること。  
2. AIが自律的に書類を更新・実装・コミットする際の権限・手順・例外処理は DEV_POLICY を参照。

### プロジェクト開始時
1. この index.md をコピーして `docs/` ディレクトリに置く。
2. プロジェクトの性質に合わない行は `不要` にして備考に理由を書く。
3. すでに存在するドキュメント（README 等）のステータスを `確定` に更新する。

### 開発進行中
1. 「これがないと進まない」と判断した書類を見つけたら、index.md のテーブルに一行追加する。
2. ステータスを `草案` → `確定` に変更する際は、レビュー記録を残す。
3. 設計変更があれば、個別ファイルと index.md の両方を更新する（index.md が陳腐化しないように）。

### リリース前
1. ★★★★★ の書類が全て `確定` になっていることを確認する。
2. `release-checklist.md` に従って最終確認を行う。
